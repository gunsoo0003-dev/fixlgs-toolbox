TOOL001 V34 Android Photo Picker random-read patch

Cause confirmed by V33:
- same PHOTO_01 alternates SUCCESS/FAIL
- input.files/change are valid
- failed runs diverge at raw provider read with NotReadableError

V34 product change:
1. remove repeated FileReader/stream reads against the same Android provider File
2. make one immediate Blob.arrayBuffer() raw-byte attempt
3. if the raw attempt fails with a transient provider error, use one structurally different image-decoder path
4. image-decoder fallback renders once to canvas and encodes a page-owned Blob
5. all downstream validation/preview/convert uses the app-owned File only
6. input value is still kept alive until capture is finished

Important:
- decoder fallback is used only after raw provider-byte access fails
- JPEG/WebP fallback is re-encoded at quality=1; PNG remains lossless canvas output
- this patch targets intermittent attachment failure, not Android/Chrome internals
