[웹도구 013 보수적 서비스 유효상한 후보]

도구 번호: 013
도구명: 이미지 합치기
route: /ko/image-merger, /en/image-merger, /ja/image-merger

중요:
- 아래 값은 일반 사용자·중간 수준 라이트 사용자를 기준으로 한 보수적 서비스 유효상한 후보이다.
- 기술적으로 가능한 최대치나 현재 제품의 기술 차단값을 서비스 목표로 삼지 않는다.
- 제품 코드의 최종 제한값으로 확정하지 않는다.
- 주작업장은 실제 PC·모바일 통합본에서 limit-only를 실행한 뒤 후보 유지/하향/상향을 판단한다.
- 후보 검수를 위해 현재 제품 코드의 기술 경고·차단값을 변경하지 않는다.

[후보 1]
항목: 한 번에 합칠 이미지 개수
후보값: 20장

[선정 이유]
- 일반 사용자 충분성: 채팅·웹페이지·설명 과정·상품 이미지·업무 캡처를 한 번에 정리하는 일반적인 사용에서는 20장이면 충분히 넓은 범위다.
- PC 안정성 고려: 파일 목록·썸네일·ImageBitmap·순서 변경 상태가 동시에 유지되므로 30장 이상보다 20장이 브라우저 메모리와 UI 반응성에 안전마진이 크다.
- 모바일 안정성 고려: 스마트폰에서는 메모리와 긴 목록 조작 부담이 PC보다 커지므로 20장을 1차 후보로 두는 편이 안정적이다.
- 처리시간 고려: 파일 디코딩과 미리보기 갱신 시간이 이미지 수에 따라 누적되므로 일반 사용 흐름을 빠르게 유지하기 좋다.
- 메모리 부담 고려: 압축 파일 크기와 별개로 디코딩된 이미지 메모리가 누적되므로 개수를 과도하게 높이지 않는다.
- 그 이상에서 추가 사용자 효용: 20장을 넘어가는 대규모 스크린샷 묶음은 일부 파워유저에게는 유용하지만 기본 서비스의 일반 사용자 효용 증가는 상대적으로 작다.

[전문 사용자 영역]
- 21장 이상 대량 합치기, 매우 많은 고해상도 사진의 일괄 결합은 기본 후보에서 제외하고 실제 수요 확인 후 확장 검토.

확신도: 보통
주작업장 재판단: 실제 모바일에서 20장 업로드·재정렬·삭제·초기화가 부드러운지 확인 후 최종 판단.

[후보 2]
항목: 결과 이미지 한 변 길이
후보값: 10,000px

[선정 이유]
- 일반 사용자 충분성: 10,000px면 일반적인 긴 스크린샷, 블로그 과정 이미지, 여러 사진 이어붙이기에 충분한 길이다.
- PC 안정성 고려: 현재 제품 경고 시작점 12,000px보다 낮아 Canvas 크기에 안전마진을 둔다.
- 모바일 안정성 고려: 모바일 브라우저의 Canvas·메모리 편차를 고려해 경고 시작점까지 서비스 목표를 끌어올리지 않는다.
- 처리시간 고려: 12,000px 이상보다 생성·인코딩·다운로드 지연 가능성을 낮춘다.
- 메모리 부담 고려: 결과 한 변이 커질수록 총 픽셀과 인코딩 부담이 급격히 커질 수 있으므로 보수적으로 잡는다.
- 그 이상에서 추가 사용자 효용: 10,000~12,000px 구간은 일부 긴 캡처에는 유용하지만 일반 사용자 대부분에게 필수 범위는 아니다.

[전문 사용자 영역]
- 10,001px 이상 초장축 결과, 현재 기술 경고점 12,000px 근처 작업은 기본 서비스 후보에서 제외하고 필요 시 확장 검토.

확신도: 높음
주작업장 재판단: 일반 PC와 모바일에서 10,000px 결과의 실제 생성·인코딩·다운로드 안정성 확인.

[후보 3]
항목: 결과 이미지 총 픽셀
후보값: 25,000,000px (25M pixels)

[선정 이유]
- 일반 사용자 충분성: 5,000×5,000 또는 2,500×10,000 수준으로 일반 사진 합치기와 긴 스크린샷에 충분하다.
- PC 안정성 고려: RGBA 원시 버퍼 기준 약 100MB 수준이며 입력 Bitmap·미리보기·인코딩 메모리를 더해도 64M 경고점보다 충분한 안전마진이 있다.
- 모바일 안정성 고려: 64M 픽셀은 원시 버퍼만 약 256MB가 될 수 있어 일반 스마트폰·여러 탭 환경에는 공격적이다. 25M을 1차 후보로 두는 편이 현실적이다.
- 처리시간 고려: 대형 PNG/WebP 인코딩 시간을 줄여 웹도구의 즉시성에 더 적합하다.
- 메모리 부담 고려: 최종 Canvas와 출력 인코딩이 동시에 메모리를 사용할 수 있어 기술 경고값보다 훨씬 낮은 서비스 후보가 안전하다.
- 그 이상에서 추가 사용자 효용: 25M을 넘는 고해상도 합성은 일부 전문·인쇄·대형 사진 작업에서 의미가 크고 일반 웹 사용에서는 추가 효용이 제한적이다.

[전문 사용자 영역]
- 25M 초과 고해상도 합성, 64M 경고점 근처 작업, 100M 기술 차단점 탐색은 기본 서비스 후보에서 제외.

확신도: 보통
주작업장 재판단: 모바일·저사양 환경에서 25M 결과 실제 생성과 다운로드 성공률을 확인해 유지/하향 여부 판단.

[현재 기술값과의 구분]
현재 제품 코드 기술 경고/차단값은 그대로 유지한다.
- 결과 한 변 경고: 12,000px
- 결과 한 변 차단: 16,384px
- 총 픽셀 경고: 64M
- 총 픽셀 차단: 100M

위 값은 기술적 안전장치이며, 이번 서비스 후보 10,000px / 25M과 동일한 의미가 아니다.

[이번 단계에서 후보를 별도 확정하지 않은 항목]
1. 개별 파일 바이트 용량
   - JPG/PNG/WebP는 압축률 차이가 커 MB만으로 디코딩 메모리 부담을 정확히 설명하기 어렵다.
   - 현재 제품 코드에 파일 용량 제한이 없으며, 임의 MB 제한을 만들지 않는다.
2. 총 입력 파일 바이트 용량
   - 동일 이유로 이번 후보에서는 별도 MB 제한을 제안하지 않는다.
3. 개별 입력 이미지 최대 해상도
   - 실제 디코딩 메모리에 중요하지만 현재 제품 제한과 모바일 실측 근거가 없다.
   - 주작업장 실측 결과가 쌓인 뒤 필요하면 별도 후보를 정한다.

[limit-only 조정 위치]
파일: tests/helpers/tool-013-limit-profile.ts

서비스 후보:
- TOOL013_SERVICE_LIMIT_CANDIDATES

검수 단계값:
- TOOL013_SERVICE_LIMIT_TEST_VALUES

주작업장이 후보보다 확장할 필요가 있다고 판단한 경우 위 파일의 후보/단계값만 조정한다.
제품 코드 상수는 수정하지 않는다.

[기본 테스트값]
이미지 개수:
- 일반 정상값: 8
- 후보 직전: 19
- 후보: 20
- 후보 소폭 초과: 21
- 8/19/20/21 각각 독립 페이지 상태에서 준비 완료까지 확인하도록 구성

결과 한 변:
- 후보 직전: 9,999px
- 후보: 10,000px
- 후보 소폭 초과: 10,001px
- 10,000px 후보에서는 실제 결과 다운로드 생성까지 실행하도록 구성

결과 총 픽셀:

- customWidth 4,999: 후보 직전

- 25M 후보에서는 실제 Canvas 생성·인코딩·다운로드까지 실행하도록 구성

[추가 탐색 가능 여부]
가능.
단, 주작업장이 일반 사용자 서비스 범위에서 더 높은 값이 실제로 필요하다고 판단한 경우에만 profile 값을 단계적으로 조정한다.
기술 파괴 한계를 찾기 위한 무한 증가 검수는 기본 limit-only에 포함하지 않는다.
