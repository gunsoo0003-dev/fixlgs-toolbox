TOOL001 V46 CHROME PASSIVE DEEP DIAGNOSTICS
기준: V45 3-WAY 원인격리 완료 후 Chrome 내부 경계만 집중 관찰

[V45에서 확보된 결론]
- Chrome 최소 HTML: 유효 7/7, PASS 3/7, FAIL 4/7.
- 실패는 NotReadableError 계열.
- Android Native GET_CONTENT: 7/7 PASS.
- Android Native PICK_IMAGES: 7/7 PASS.
- 따라서 TOOL001/React/Next.js를 제거해도 Chrome에서 랜덤 byte-read 실패가 재현되고,
  같은 Android 네이티브 직접 read 두 경로는 안정적으로 통과했다.
- 다음 조사 대상은 Chrome이 Android 선택 결과를 웹 File/byte read로 연결하는 경계다.

[V46 목적]
- 원인격리를 다시 반복하지 않는다.
- Samsung Internet 검사 없음.
- Native 진단 APK 검사 없음.
- Chrome 최소 HTML 7회만 유지한다.
- 실제 사용자 흐름과 byte-read 동작은 V45 Chrome 최소 HTML 방식 그대로 유지한다.
- 성공/실패 사이의 Chrome/Android 시스템 관찰 증거를 더 깊게 저장한다.

[검수 철학]
- 검수기는 검수/관찰/기록만 한다.
- 한 회차 = input 클릭 -> Photo Picker -> PHOTO01 1회 선택 -> file.arrayBuffer() 1회 -> 판정.
- 실패 복구 없음.
- read retry 없음.
- 같은 File 재획득 없음.
- 다른 사진 선택 없음.
- grid/좌표 fallback 없음.
- HARNESS_FAIL은 browser/product byte-read FAIL로 계산하지 않는다.

[V46 추가 계측 - 동작 비변경]
1) Playwright page 이벤트 저장
- console
- pageerror
- crash
- requestfailed

2) CDP 관찰 이벤트 저장
- Runtime.exceptionThrown
- Runtime.consoleAPICalled
- Log.entryAdded
- Inspector.targetCrashed
- CDP attach가 지원되지 않으면 그 사실만 기록하며 제품 FAIL로 처리하지 않음.

3) Android passive 로그 저장
- logcat -b all 전체 buffer
- Chrome/PhotoPicker/MediaProvider/URI/permission/file 관련 deep-filtered log
- Chrome 프로세스 전/후 snapshot
- activity/window foreground 관련 snapshot
- activity providers / Chrome package URI-permission 관련 snapshot

4) 최소 HTML 진단값 추가
- changeAt / readStartAt / readEndAt
- readDurationMs
- File name / size / type / lastModified
- visibility / focus / userAgent
- 실제 byte read는 기존과 똑같이 file.arrayBuffer() 단 1회

[중요: Chrome 동작을 바꾸는 계측 금지]
- chrome-command-line 파일 생성 안 함.
- --enable-logging / --v 플래그 주입 안 함.
- set-debug-app 안 함.
- Chrome feature flag 변경 안 함.
- retry/fallback/recovery 없음.
- 즉 V46은 기존 Chrome 상태에서 로그와 이벤트만 수집한다.

[APK]
- V46은 Native 진단 APK를 아예 사용하지 않는다.
- 따라서 설치/삭제 과정 자체가 없다.
- 향후 Native APK를 다시 사용하는 진단본이 생기면 결과 저장/ZIP 완료 후 자동 삭제 원칙 유지.
