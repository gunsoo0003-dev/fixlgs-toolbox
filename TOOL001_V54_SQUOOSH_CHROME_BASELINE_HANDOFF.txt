TOOL001 V54R1 SQUOOSH CHROME BASELINE

목적
- V53R2에서 Chrome native multipart는 유효 7회 중 3회 성공/4회 실패, Firefox는 유효 6회 중 6회 성공이었다.
- 다음 단계는 같은 Android/Chrome에서 외부 기준점 Squoosh가 PHOTO01을 얼마나 안정적으로 여는지 확인한다.
- 이번 버전은 제품 수정이 아니라 원인 분리용 외부 기준점 검수다.

검수 대상
- https://squoosh.app/
- Chrome: com.android.chrome
- PHOTO01: 기본 1000008533.jpg
- 7회

실행 원칙
- 각 회차 fresh Chrome force-stop 후 Squoosh production site 진입
- Squoosh의 실제 visible Open 버튼을 Playwright 일반 click으로 정확히 1회 클릭
- Android Intent Resolver가 실제로 뜨면 '사진 및 동영상' 항목만 정확히 1회 탭
- V39 원본 Photo Picker 함수 9개는 그대로 유지
- PHOTO01 1회 선택
- 실패 시 재선택/retry/recovery/다른 사진 없음
- 검수기가 provider File bytes를 읽지 않음
- Squoosh DOM/파일 input 속성 수정 없음

SUCCESS 판정
- 실제 Squoosh editor(/editor) 진입
- two-up preview canvas 2개가 화면에 보임
- 두 canvas의 intrinsic width/height가 0보다 큼
- 렌더된 canvas 중앙 픽셀 alpha가 0보다 큰 preview가 확인됨
- 마지막 실기기 스크린샷을 매 회차 저장

FAIL/HARNESS 분리
- PHOTO01 선택이 정상 완료된 뒤 editor preview가 뜨지 않거나 Source decoding error가 발생하면 Squoosh/Chrome FAIL
- Squoosh 페이지 미로딩, CDP 관찰 연결 실패, picker 탐색 자체 실패 등 검수기/환경 문제는 HARNESS_FAIL
- HARNESS_FAIL은 제품/브라우저 실패율에 포함하지 않음

중간 chooser 관련
- Firefox 때 실제로 관찰된 Android Intent Resolver는 '카메라'와 '사진 및 동영상'을 제시했다.
- V54R1은 이 중 '사진 및 동영상'만 정확히 1회 선택한다. 이는 실패 복구 fallback이 아니라 실제 사용자 흐름의 중간 선택 단계다.

Squoosh 공개 구현 비교 근거
- Squoosh Intro는 hidden input[type=file]을 두고 visible Open 버튼이 file input을 연다.
- file change 후 input value를 초기화하고 File을 앱으로 넘긴다.
- 파일 선택 후 URL은 /editor로 전환된다.
- decode된 source/preprocessed ImageData는 two-up canvas에 그려진다.
- 따라서 V54는 /editor + 실제 preview canvas 렌더를 성공 기준으로 사용한다.
