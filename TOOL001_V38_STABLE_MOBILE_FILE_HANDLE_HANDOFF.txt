TOOL001 V38 - Android Chrome stable file-handle picker patch
Date: 2026-08-12

Purpose
- V37 proved FileReader / Blob.arrayBuffer / Blob.stream all fail randomly on the same provider-backed File.
- Move the mobile acquisition boundary above those read APIs.

Behavior
1) Android Chrome with showOpenFilePicker support:
   - use File System Access picker instead of legacy input click
   - retain FileSystemFileHandle
   - handle.getFile() -> arrayBuffer()
   - if provider read is transiently unreadable, reacquire a fresh File from the SAME handle and retry
   - after first successful bytes read, create app-owned Blob/File
   - all existing TOOL001 inspection/preview/conversion uses only the app-owned File
2) Desktop / unsupported browsers:
   - keep the existing <input type=file> path unchanged
3) User cancel (AbortError):
   - do not reopen the legacy picker

Files
- lib/image-input-capture.ts
- components/image-converter-tool.tsx
- scripts/verify-tool-001-v38-stable-mobile-picker.mjs

Static verification
node scripts/verify-tool-001-v38-stable-mobile-picker.mjs

Important
- This is a structural fix candidate for the Photo Picker/provider -> Chrome File boundary.
- It is not declared fixed until real-device repeated attachment reaches 100%.
