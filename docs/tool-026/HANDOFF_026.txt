3. PDF implementation
No new npm dependency was added. The implementation uses a small 026-dedicated PDF 1.4 writer in lib/tool-026-pdf.ts.
Browser decode/canvas normalizes JPG/PNG to opaque JPEG page image data, then embeds it as DCTDecode XObject. This intentionally avoids server conversion and avoids adding a package when the confirmed 026 scope can be satisfied locally.
A4/Letter point constants and mm->pt conversion live in PDF_PAGE_PRESETS/mmToPt. Preview/layout and PDF drawing use the same orientation/margin/contain model.

11. Known design/technical intent
026 is not OCR, PDF editing, merging existing PDFs, encryption, compression, signing, or PDF-to-image. Those belong to adjacent PDF tools.
The JPEG-normalization strategy preserves visible appearance and PNG transparency against a white PDF page, but it is not lossless original-image embedding. This matches the delivery scope focused on document creation and stable local processing; main-workshop visual/file-size tests should confirm acceptable output quality.
